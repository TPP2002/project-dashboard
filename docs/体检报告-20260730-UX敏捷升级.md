## 二、功能空白（本次新增）

### N1【核心交付】「每日成果」页 `/daily`
用户每天在多个项目推进大量任务卡，但看板只有"累计进度"，**没有任何"按天"的视角**——
"今天干完了几张卡？这周节奏怎么样？哪天效率最高？"完全无法回答。敏捷管理里这是
吞吐量（Throughput）追踪，是节奏管理的基本盘。

新增内容：
- 顶部统计卡：今日完成 / 本周完成 / 本月完成 / 连续有产出天数（连击）
- 产出热力日历（GitHub 风格，近 ~17 周）：每天一格，颜色深浅 = 完工卡数，点格子看当天明细
- 近 30 天完工柱状图（echarts 懒加载，含 7 日移动平均线，识别节奏波动）
- 选中日期的"当日成果清单"：完工卡（可点开抽屉）+ 当天拍板/认领/进度更新等动作统计
- 项目范围切换：默认「全部项目」（工作总量视角），可切回单项目
- 侧栏新增「📆 每日成果」入口，今日完成数 > 0 时显示绿色徽章

完工日期口径（重要）：
- 一张卡记入某天，条件 = 当前状态「已完工」；完工日优先取该卡活动流里**最后一条
  type='done' 事件的精确时间戳（转本地时区日期）**，无 done 事件时兜底用 `dates.done`。
- 为什么不直接用 `dates.done`：见 BUG B3——旧数据里它可能差一天。

### N2 总览页补"今日完成"
- 汇总栏加「今日完成」卡片（点击进 /daily）
- 每个项目卡加「今日 +N」徽章——早上打开看板第一眼就知道昨晚/今天各项目动没动。

## 三、BUG（本次修复）

### B1 活动流"先截断、后筛选"——筛选结果严重漏数据
`store.globalActivity` 全局只取前 60 条（`mergeActivity` 默认 limit=60），活动流页面的
项目/类型筛选是在这 60 条里做的。mama 一个项目就有 2706 条活动——想筛"done"看历史完工，
最多只能看到最近 60 条里碰巧有的几条，**旧记录永远筛不出来**。
修复：全量派生（跨项目 4620 条，一次排序毫秒级），页面内先筛选再分页显示（每页 100 条 + 加载更多）。

### B2 活动流类型下拉不全
类型选项也是从截断后的 60 条里归纳的——status/blocked 等低频类型根本不出现在下拉里。随 B1 一并修复。

### B3 CLI 日期口径用了世界时（UTC）——凌晨完工被记到"前一天"
`cli/commands.cjs` 的 `today()` 用 `toISOString().slice(0,10)`，是 UTC 日期。
北京时间 = UTC+8，**凌晨 0:00–7:59 的完工/开工/拍板/落地日期全被记成前一天**。
负责人经常深夜施工，这个错必然已发生在存量数据里。
修复：`today()` 改为本地日期；存量数据不回改（前端统计口径已优先用活动流精确时间戳，见 N1，
所以旧数据统计仍准确；有 done 事件的 329 张卡都不受影响）。

### B4 甘特图"依赖箭头"是死代码
Gantt.vue 注释宣称"箭头=依赖"，实际构建的 arrows 数组从未被渲染进图表——功能没实现，
代码还在每次重绘时白算一遍。处理：删除死代码（依赖关系已有专门的「依赖」页，甘特上画箭头徒增视觉噪音）。

### B5（小）活动流列表用纯 index 做 key
实时推送新增记录时列表前插，index key 导致 DOM 错位复用。改复合 key。

## 四、可用性欠账（本次升级）

### U1 验收矩阵被已完工淹没
137 行全量表格里 132 行是已完工——每次打开都要在绿灯海里找活跃任务。
升级：接入全站统一的 DoneToggle（默认折叠已完工），与看板/波次/甘特/依赖行为一致。

### U2 看板页已完工泳道无排序
展开已完工泳道时 132 张卡按入库顺序排，找"最近完工的那张"要翻很久。
升级：已完工泳道按完工日倒序（最新完工在最上面）。

### U3 类型缺失
`lastProgressAt` 在 TaskCard/TaskDrawer 里以 `as any` 使用，types.ts 没这个字段。补上。
侧栏版本号 v0.1 与 package.json 1.0.0 不一致，对齐。

## 五、体检后判定"健康、不动"的部分

- CLI 写通道（claim/progress/done/decide）：多项目多对话依赖的稳定协议，除 B3 外不动。
- server.cjs：路径安全、SSE、防注入均按风险登记册落实，无发现问题。
- 依赖图/波次/占用防撞/搜索/待拍板/待落地：功能完好，交互一致。
- 深色主题与整体设计系统：保持。
