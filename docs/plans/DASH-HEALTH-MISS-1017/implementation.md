# 健康未响应时阻止重复启动

关联卡：DASH-LAUNCHER-HEALTH-MISS-EXISTING-1014。基线：4a0e73ca2034c759d3da185b918f09b15106d6d4。

旧启动器把没有健康响应直接分类为 none。即使本机归属记录中的服务进程仍在运行，预检和发布后的第二次检查都会继续安装、发布、覆盖归属登记并启动新实例。生产中已出现旧服务占用原端口、新服务移到下一端口的双实例情况。

classifyInstance 现在在健康响应缺失时复用现有 validRecord 与 pidAlive：有效本机记录的进程仍活着，或者查询无法确认其退出时，明确拒绝新启动。仅 ESRCH 确知退出时保留原启动路径。PID 查询只发送信号 0，用于保守阻止重复启动，不作为归属、复用或停止进程的充分证明。两次分类都接入相同的进程查询依赖。

健康响应存在时，原有归属、票据与模式核验不变；同版本复用、旧版本有序换新、停止失败拒绝新启动等行为不变。没有放宽超时，没有自动强杀或周期重启。这项修复不证明每一次健康无响应的具体原因。
