## 实现边界

- `core/schedReadExecutor.cjs` 持有一个惰性创建、同一共享根下复用的 `worker_threads.Worker`。只允许一个读取实际执行，主线程不再执行调度快照、分页、导出或详情/关联的完整历史读取。
- `server/schedReadWorker.cjs` 直接调用原 `schedRead` 的 `snapshot`、`ticketPage`、`exportTickets`、`ticketDetail`、`relatedTickets`。完整读文件、UTF-8、SHA、票据校验、台账解析、估算及既有缓存算法均保持原样；没有完成响应缓存、TTL、mtime 或 cursor 免读。
- `server/schedApi.cjs` 保持同步返回路由是否命中的约定，异步发送读结果。指令提交、权限、模块开关、轻量 `pollStamp` 和事件语义保持现状。CSV 内容/响应头、`related=0`、原有 400/404/503 和不可读返回结构沿用原逻辑；工作线程传回的异常显式保留 message/name/code/status。
- `server/server.cjs` 的原轮询负责观察空闲线程的共享根切换，服务 close 负责关闭执行器。原有三个 interval 不增加；原主线程票据缓存的 sweep/clear 接入换成线程生命周期接入。

## 并发与回收

| 对象 | 上限或回收边界 |
| --- | --- |
| 实际读取工作线程 | 最多 1 个；终止 Promise 完成后才允许创建替代线程 |
| 未完成读操作 | 最多 16 个，包含正在运行的操作；其余串行等待 |
| 等待结果的调用方 | 全局最多 128 个，包含相同操作的订阅者；超限走既有 503 不可读错误结构 |
| 相同操作 | 仅合并执行中或排队中的相同 share/action/query；查询字段按名字排序，字段值保持原样；不同共享根、操作或查询不会串结果 |
| 快照时间 | 同一未完成快照共用首个调用方的 nowMs；完成后删除合并项，下次请求重新取时、完整读取 |
| 客户端断线 | req aborted 或 res close 触发该调用方的 AbortSignal；立即删除其等待对象和监听器；尚未执行且无人等待的操作立即出队 |
| 正在读取但已无人等待 | 只保留最多一个活动操作描述，不保留 HTTP 等待对象；让该次同步读取结束，避免中断同一线程上的共享工作或另开线程重复扫盘 |
| 空闲线程 | 队列排空后设一个 unref 的单次 10 分钟计时器，工作到来即撤销；到期终止线程，释放它持有的全部私有缓存与堆对象 |
| 共享根切换 | 新共享根开始执行前先终止旧线程；无新读请求时由服务既有 sweep 观察切换并释放空闲旧线程 |
| 异常/异常退出/消息异常/发送失败 | 当前操作、合并订阅者及排队操作全部失败、移除监听器；终止原线程；不自动重跑，下次新请求才创建新线程 |
| close | 幂等；拒绝当前及排队调用，清计时器和监听器，等待线程终止；关闭后拒绝新读。若终止本身失败，保持关闭并向 close 调用方报告，禁止冒险创建第二个线程 |

每次实际读取有 60 秒单次失效期限，避免异常卡住时永久占住唯一工作线程；成功、失败和关闭均撤销该期限计时器。超时拒绝当前和排队请求并终止线程，下一次新请求可以恢复，不自动重跑。没有放宽原 HTTP/测试期限，也没有强制 GC、周期重启或通用任务框架。计数上限不是 V8 堆/RSS 的硬限额。

主控补充了 `messageerror` 的失败回收和监听清理。真实 `server.close()` 在等待 HTTP 连接排空之前关闭读取执行器，令在途读请求返回原结构的 503，而不是等到 close 事件后才清理。原 close 回调与返回值保持不变。
