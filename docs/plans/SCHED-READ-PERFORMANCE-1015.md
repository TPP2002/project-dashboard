# 调度读取性能第一轮：只复用账本验证

> 状态:评估件 · 事实基线 master@8cce47f · 关联卡 AD-20261015-SCHED-READ-PERFORMANCE · 最后核对 2026-10-15

取证先行，第一轮只优化账本的重复验证；没有改变票据读取、历史聚合、页面刷新频率或接口响应的缓存策略。

隔离数据包含 12,813 份票据（77,387,239 字节）、35 份日账本（46,084,384 字节）。Node v24.14.0 下，原快照耗时约 2.10—2.22 秒，其中账本读取与验证约 0.77—0.82 秒，响应编码不足 0.1 毫秒。这里是源码调用的受控测量，不能解释成每隔五秒产生同等物理磁盘读取。

实现仅复用已经完整验证的文件内容指纹。每次仍枚举目录、读取完整文件、验证 UTF-8、计算完整输入 SHA256、解析新对象，并检查本次目录内的全局事件顺序。新内容、截断、替换或损坏内容会走原字段与逐事件 SHA256 验证；不以 mtime、长度、cursorSeq 或旧响应判断新鲜度。

验证缓存一次只服务一个目录，最多 64 个文件、2,048 字节摘要。目录切换、文件移除会回收，容量不足按最近使用顺序淘汰。它不保留原始文件、解析对象或历史响应。最初保留原字节的试验增加约 50 MiB 驻留内存，已放弃该实现。

时钟、心跳、倒计时、七天项目窗口、耗时估计、票据和回执继续在每次调用中读取或计算。首轮冷态仍执行完整验证；被淘汰的历史文件也重新验证。缓存失效只影响成本，不允许读失败变成空队列或成功。

冻结数据的新旧入口比较覆盖 44 个观测：snapshot、筛选、分页、详情、关联、导出及原有 10,000 行上限错误、时钟推进、票据状态、新单/跨 attempt、回执、账本追加/截断/未知文件及恢复，结果结构与语义一致。坏内容、同长度且恢复 mtime 的改写、跨日顺序、替换、删除、读取失败和双容量上限另由回归测试约束。原断言和超时均保留。

最终验收仍要求：同机、同冻结数据至少三组成对的冷态/暖态/输入变化数据；收益超过自然波动；项目必要检查和最终 SHA CI；正式 release；6060 健康版本与真实页面验收。每层原始证据、性能数字与交付状态登记在关联卡及本轮本地证据包。源码合并不能代替发布和真实页面验收。
