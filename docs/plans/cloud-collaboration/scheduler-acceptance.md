# 调度迁移实际验收清单

状态：实现中，下面是必须通过的验收条件，不是通过记录。

云端只拥有调度账本、排队、准入、许可和指令回执；执行节点保留 Windows 进程身份与 jobs-v12 生命周期实物的唯一写入权。原生进程观察不能在 Linux 上按同号 PID 推断。

| 场景 | 必须证明的实际行为 |
| --- | --- |
| 开始执行 | 获得真实 controller 出生身份后，上报 started；持久业务接受、对应游标投影和有效原生租约全部成立才释放暂停创建的子进程。仅持久收件、目录 running 或投影 running 均不够。 |
| started 回执丢失 | 回执丢失时不运行子命令；相同操作重试最多产生一个 started 事件和一棵子进程树。 |
| 节点卡死与断租 | Node 主线程阻塞且 stdin 管道仍开时，原生宿主独立计时器仍按截止时间终止 JobObject。 |
| 租约时钟 | 原生宿主保存 challenge 发出时刻；跨进程不传未经换算的绝对单调时钟。延迟、重复回复不得从接收时刻重新获得 TTL。 |
| 身份漂移 | PID 复用、旧代际、旧会话、未知事实和旧投影都不能放行或误杀新的进程树。 |
| 未开始与拒跑 | notStarted、refused、空退出码和补跑计划完整往返，仍进入原来的重排、钉回或补跑分支；不编造已开始的 controller。 |
| 常驻登记 | hold 不走 started 或 JobObject 执行路径，仍能登记、续约和释放；断线不能擅自杀既有应用或把未知当已停止。 |
| 当前读模型 | 空队列仍能读取配置和心跳；queued、unsatisfiable、registerOnly、resident、终态和完整许可信息可读取。 |
| 控制操作 | 取消、暂停、恢复、预留与 owner-hold 操作影响原有正确机器；Ubuntu authorityHost 与 Windows ownerMachine 分开。 |
| 传输与重放 | 不可变操作跨 SSH 断线可用原编号重试且至多生效一次；实时心跳不能离线排队后补发续命。 |
| 交接事务 | jobs-v12 发布前后崩溃、丢失 ACK、claim/transition 未决都不重复派发；未知状态不得当 absent。 |
| 来源证明 | 从原始提交对象的 ACL 或经认证本机 IPC 调用者 SID 核验来源，并绑定提交哈希；不得把网关重写副本的所有者当原提交者。 |
| 会话归属 | 一个常驻 gateway 独占节点上行会话与序号；多个 CLI 通过受保护语义 IPC 调用，不能各自替换活连接。 |
| 带宽与缓存 | Windows 按需获取带 hash/cursor 的有限不可变对象；不在每拍全量同步台账。云端页面可读同机权威目录。 |
| 发布切换 | 先升级并核验读者，再停旧 writer 和自动重启来源，检查无并行写者后启用新权威。 |
| 独立部署 | 公开安装及其依赖闭包不回指开发者的私有仓库、目录、机器或账号；使用自己的配置完成真实任务闭环。 |

完整任务执行链还须验证菜单识别、自动搬单、快照、产物、日志、常驻进程、CI 让路，以及各项目正式入口。部署、功能通过和资源节省分别报告；没有等价负载证据不声明具体性能增益。
