# 调度迁移契约

状态：设计与实现中，尚未切换生产调度。负责人已确认本轮迁移底层调度，并接受完整开发与验证时间。

## 运行边界

云端运行唯一调度派单进程，拥有调度账本、排队、准入、许可、取消意图和回执。Windows 代理负责本机进程身份核验、执行、挂起与回收，以及向云端上报经过核验的机器事实。执行任务的机器仍须在线。

现有集群任务生命周期另有独立的租约与状态转换规则。迁移时保留其唯一写入权威，通过有限的交接接口调用，不把生命周期目录复制到云端后再次写入。不得用双向目录同步制造两个调度账本或两个生命周期权威。

公开部署包不能依赖任何私有仓库、固定机器名、真实项目路径、GitHub runner 身份或本机共享盘。部署者提供机器目录、项目菜单及资源策略；缺少配置时拒绝执行对应功能，不自动采用开发者环境。

## 分工接口

- 机器事实接口：返回经过认证、带时效与机器身份的容量、心跳、任务来源证明和进程出生身份观察。
- 任务交接接口：按完整任务与执行身份请求发布、观察或隔离。网络请求在调度租约保护区外完成，结果在后续节拍核验并记账。
- 本机投影接口：为同步许可核验保留只读缓存，但所有读取必须检查云端权威代际、完整批次水位和新鲜度；断线后不能继续使用过期许可。

任务提交、执行报告和操作指令使用不可变身份与幂等内容哈希。心跳、等待与常驻租约使用单调序号和连接代际，旧文件重传不能刷新存活时间。取消与远程终止必须绑定任务、执行代次和实际进程出生身份。

云端不得用 Linux 上同号 PID 的存在性推断 Windows 进程存活。来源所有权须由 Windows 操作系统核验，不能信任客户端自行声明的 SID 或 trusted 字段。

## 交付顺序

1. 抽取可独立安装、构建与运行的通用核心，保留原状态机、原子写、租约围栏和准入规则；给私人配置建立明确输入。
2. 实现消息传输、机器事实、投影新鲜度和单次执行闭环。在隔离环境中由真实 Linux 派单，真实 Windows 领取许可并执行。
3. 接入跨机器任务交接、快照与产物，验证已启用菜单、挂起恢复、取消、死亡回收、后台常驻和调度管理页面。
4. 升级客户端和代理读者，确认运行版本，再启用新写者。停止旧写者及其自动重启来源，迁移经过校验的账本与控制数据，保留可恢复备份。

新的传输格式必须让旧客户端明确拒绝；不能只新增一个会被旧客户端忽略的 capability 字段。不得先启用写者，再等待旧代理自行升级。

## 必须保留的证据

| 场景 | 通过条件 |
| --- | --- |
| 正常任务 | 提交、授予、started 回执、执行、finished 回执、日志与看板一致 |
| 重传与丢回执 | 相同消息无重复执行；同身份异内容拒绝；重启后仍可幂等重试 |
| 断网 | 过期投影不能开新任务；执行按约定停机或收尾；重连不复活旧执行 |
| 进程与机器故障 | PID 复用不误认；未知身份不误杀；代理重启后旧出生身份不复用 |
| 云端重启与双实例 | 恢复已提交账本；租约围栏阻止两个写者；旧代际许可拒绝 |
| 跨机器搬单 | 快照与内容哈希匹配；任务只由一个生命周期权威发布和转换 |
| 升级与回退 | 旧读者明确拒绝新格式；切换无并行写者；恢复使用单一已校验数据副本 |

功能测试、实际部署和资源节省分别报告。没有同等负载的测量，不宣称具体 CPU 或内存降幅。
