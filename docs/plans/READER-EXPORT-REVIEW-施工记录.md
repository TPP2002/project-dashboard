# READER-EXPORT-REVIEW 施工记录:审阅台加「导出给外脑」按钮

工单要求:负责人 2026-09-19 提出「把打了批注的报告连同批注导出来,直接传回外脑继续讨论,
不用每次找 Claude」。当天已用一段未入库的 Python 脚本手工出过一份格式获认可的 md,
本单把它做成审阅台里的按钮:点「导出给外脑」→ 弹对话框 → 下载或复制一份
「批阅意见单 + 回流对账 + 带批注的报告原文」,直接贴给外脑。

按派单方给的五步顺序逐条落地。机验(全量单测、打包)由派单器统一重跑;
施工过程按算力规矩没有运行测试入口,自查用的是 `node -e` 直跑代码复刻断言(见下文「验算」)。

## 五步对照

1. **纯函数模块** `server/readerReviewExport.cjs`(新增):导出 `buildReviewExport({meta, batch, md, annos, notes, today})`
   与 `exportFileName(title, today)`。不碰 HTTP、不读盘、不写盘;`today` 由调用方注入,
   同一份入参永远拼出同一个字符串。输出三节:
   - 标题行 `# 批阅意见单 · <标题> <版本> → 回运给外脑` + 两行引用(批阅日期、事实基线、批注条数、类型口径);
   - **A. 逐条意见**:六列表格,按批注 `at` 升序(内部排序,与参考实现一致);类型=文本含
     问号或「为什么/是否/能不能」任一 → 追问,否则批注;两栏「要求外脑做什么」按类型给固定文案;
     单元格里 `|` 转义为 `\|`、意见换行压成 `<br>`、引用换行压成空格;无批注写「(暂无批注)」;
   - **B. 回流对账**:只收 kind 为 纠正/改判/冲突 的边注,`**B<n>. [<kind>] <anchor>**` + 正文,
     正文里「你」全部换成「负责人」;一条没有时整节连标题都不出现;
   - **C. 报告原文**:先剔「入库说明」,再把每条批注按 `> **【负责人批注 <编号>】**(针对:「<quote>」)`
     + 逐行加 `> ` 的引用块插进它所在小节末尾,编号与 A 表一致;定位不到的集中放在 C 节最前
     「未能定位到具体页的批注」下,不许丢。
2. **测试** `test/readerReviewExport.test.cjs`(新增):①~⑦ 钉纯函数(标题与引用行、A 表升序与归类与
   转义、暂无批注、B 节筛选与「你→负责人」与整节隐藏、C 节剔除/插入/编号/未定位集中、定位通用版、
   入库说明判定边界、文件名),⑧ 钉路由:用假依赖直驱 `createReaderApi` 的 route 表(不起真服务),
   断言 200 回 `ok/fileName/md/annoCount`、key 非法 400、项目未注册 404、报告不存在 404、非 GET 不接,
   另有一条钉住 `report` 路由返回体字段与既有契约一致(见第 3 步)。已挂进 `package.json` 的
   `test:fast`(注释同步改真)。
3. **路由** `server/readerApi.cjs`:把 `handleReport` 里的读取段抽成同文件内的内部函数
   `loadReportBundle(projectId, key)`(清单定位 → 正文 → 上一版 → 边注 → 本机批注),`handleReport`
   与新增的 `handleExportReview` 共用;**`handleReport` 的返回体字段、取值与键序逐字节未动**。
   route 表加一行 `export-review`(仅 GET)。响应:200 `{ok, fileName, md, annoCount}`,
   `fileName` 形如 `批阅意见单-<报告标题>-<YYYYMMDD>.md`;「批阅日期」取本机日历的今天

   显示文件名与批注条数、前 60 行只读预览(超出显示「…共 N 行」,完整内容随下载/复制带走)、
   「下载 .md」走 Blob + a[download]、「复制到剪贴板」走 `navigator.clipboard`(失败则选中预览内容

## 关键判断与理由

### C 节标题的「页」改「小节」

参考实现 C 节标题写「(负责人批注已插在对应页末尾)」,因为它只认「## 第 N 页 · 」一种标题。
工单把定位规则升级成通用版(认任意 1~6 级标题),批注落点不再都是「页」;工单对 C 节的描述
原文就是「插在它所在小节的末尾」,故标题写「(负责人批注已插在对应小节末尾)」。三节结构与
其余文案逐字对齐,「未能定位到具体页的批注」标签照工单原文保留。

### 定位规则(通用版)的实现口径

- 标题 = 常见 markdown 形态的 1~6 个 `#` + 空格 + 文字;anchor 取「标题文字包含 anchor」的**第一个**
  命中(与参考实现的取法一致,重复标题不会重复挂);
- 小节末尾 = 下一个**级别 ≤ 它**的标题之前,没有就到文末——子小节(更高级别数字)跟随整节,
  所以挂在整节(含子节)末尾;
- 定位在「入库说明剔除之后」的正文上做:剔除只删引用块与 `---`、保留一级标题,正文标题不受影响。

### 入库说明剔除的判定

第一个单独成行的 `---` 之前(且该行在前 40 行内)全是一级标题、引用块、空行才算「入库说明」;
剔除时引用块与 `---` 删掉、一级标题保留、段尾空行收掉;形态不合(夹了普通文字)或没有 `---`
或分隔线超出前 40 行,则原文一个字不动整段进 C 节。三种不合形态各有测试钉住。

### 文件名清洗

`批阅意见单-<报告标题>-<YYYYMMDD>.md`:标题里 `/ \ : * ? " < >` 与控制字符统一换 `-`
(Windows 文件名非法集),按码点截断保证总长 ≤ 80,截断后收掉尾部的 `-` 与空白。
`today` 传 `YYYY-MM-DD`,压成 `YYYYMMDD`。

### 「批阅日期=今天」与确定性红线

业务代码禁裸时间戳指的是「同 seed 必须同结果」的生成逻辑;导出单的批阅日期天生就是
「当天」,与 `handleAnnosPost` 里既有的时间戳写法同一性质。可测性由结构保证:
纯函数收 `today` 参数,机验全部走固定值;HTTP 层的 `localToday()` 只有取当天这一个职责。

### 为什么用假依赖直驱 route 表做路由测试

既有 `test/readerApi.test.cjs`(禁区,一字未动)走 spawn 真服务的端到端;本单的路由用例
只需要钉「路由表接了 export-review、错误分支码对、report 返回体没变」,用假
`resolveProjectSafe` / `sendJson` 直驱 `createReaderApi` 即可全覆盖,不起端口、不吃多进程,
把全量单测的时长与并发压力留在原地。清单/正文落临时目录,批注账本直写临时数据根,
虚构项目 `demo-a`,全程不碰真实数据。

## 验算(非正式机验,官方统计行以派单器重跑为准)

本机测试入口(`node --test`、npm 脚本)被环境策略拦截,与既往施工单相同。按工单允许的
替代办法,用 `node -e` 直跑 `server/` 代码,逐条复刻了测试文件里的断言:

- 探针 A(纯函数 ①~⑤):主夹具上标题行、两行引用、A 表升序/追问归类/转义/换行压排、
  暂无批注、B 节筛选与「你→负责人」与整节隐藏、C 节剔除/插入位置/编号/未定位集中——全过;
- 探针 B(⑥⑦):多级标题命中、子串匹配、只挂第一处、整节末尾、文末收尾、空 anchor 不丢、
  入库说明三种不合形态不剔、文件名非法字符/前缀/总长 80——全过;
- 探针 C(⑧ 路由):假依赖直驱,200 形状、`批阅意见单-演示报告-20260919.md`、400/404 分支、
  非 GET 不接、`report` 返回体字段与既有契约一致——全过。

测试文件本身在这一轮验算中修掉两处笔误(表格行数把分隔行误计入;路由断言漏了
批注块加粗记号),修正后探针全绿。
