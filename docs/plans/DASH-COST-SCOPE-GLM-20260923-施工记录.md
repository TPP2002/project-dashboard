# 成本监管口径与跨项目视图

2026-09-23；卡 `DASH-COST-SCOPE-GLM-20260923`。施工方=本对话自干（负责人明确要求不使用派单器）。

## 根因与改法

旧页顶部把 Claude 和 Codex 的 token 加成一个大数，又把 DeepSeek 金额、余额和缓存命中率复制一遍，右侧本来已有这些指标。这个“合计”不是钱：输入、输出和缓存读取单价不同；订阅制的 token 也不是实付款。更深一层，GLM 通过 Claude Code CLI 工作时也写进同一个对话目录，旧页把这部分计入“Claude”指标。Codex 流水已有分桶，但旧扫描器只拿累计总 token。页面请求固定带当前项目 id，没有全局账。GLM 工单 `cost.json` 已存首轮、续聊用量和周窗积分差，页面此前完全没读。

本次按数据的真实单位分开：Claude 四桶按官方型号价格折 API 直购等价美元；DeepSeek 按工单用量和本地价目折人民币；GLM 编程套餐显示周窗积分差与四桶 token；Codex 显示输入、输出和输入中的缓存子集，不凭总 token 猜实付。GLM 并发时积分差可能含同期别的工单，缺差值显示空白。未知 Claude 型号不借相近型号计价，页面列缺数。全部项目汇总按独立会话目录和代码仓去重，项目表标出共享来源；可切入单项目看明细。

## 验收重点

- Claude/GLM 混合流水不使 Claude 总量或美元错增；不同币种和积分绝不相加。
- Codex 缺输入/输出字段时不能把零当完整分桶；缓存读取是输入的子集。
- GLM 工单按目标仓归属，首轮与续聊各计一次，积分无法归因时有提示。
- 多项目总额不重复算共享目录；全部项目页可逐项切入单项目。
- 前端类型检查、构建、定向机验和排队全量机验均过；发布副本更新后才算上线。

## 价格与限制

Claude API 等价单价在 2026-09-23 对照[官方价格页](https://platform.claude.com/docs/en/about-claude/pricing)；只用于估算相同 token 直购 API 的价，不代表订阅账单。页面没有换汇，避免把美元估算、人民币折算和 GLM 积分混成一个“总花费”。本地以外的 Claude/Codex 会话不能从本机流水还原；GLM 只统计已经落盘的工单，不把没有成本记录的工作臆测为零。
