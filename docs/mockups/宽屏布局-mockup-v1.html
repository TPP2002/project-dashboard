一句话结论

现在这六个页面都被写死了内容宽度(最窄的算力页只有 860 像素),所以你在 1920 的屏幕上,右边永远空着三分之一到一半。 改法不是简单把字拉宽——那样一行字长到眼睛跟不上,反而更难读。正确做法是让卡片「分栏排队」: 屏幕宽了就自动多排一列,窄了自动收回一列,每一列的宽度始终保持在看着舒服的范围里。

另外两处顺手治掉:①看板泳道现在被钉死成 260 像素,只有四列的时候右边空一大片——改成「列少就自己长胖、列多就横向滚动」; ②宽屏下点任务卡不再弹一层灰蒙蒙的遮罩,详情直接在右边开一栏,左边的列表照样看得见、点得着。

1920 宽的窗口,去掉左侧导航栏和页面内边距,真正能放东西的地方是 1664 像素。下面是实测(不是估的,是在跑着的看板上量的): 蓝色 = 现在真的用到的宽度,红斜纹 = 白白空着的。

看板泳道那条按「四条活跃泳道」算(未完工的状态最多也就四五条),泳道越少空得越多。

02三条通用规则(六个页面共用一套)

先把规则说清楚,后面每一页就是这三条的具体样子。

规则一页面不再写死宽度

六个页面里的 max-width: 980px / 1040px / 1120px / 860px / 900px 全部删掉,页面本身占满可用宽度。 宽度不再由「页面」控制,改由下面第二条的「卡片」控制。

规则二卡片自动分栏

内容区改成会自己数格子的栅格:repeat(auto-fill, minmax(下限, 1fr))。 意思是「每一列不许窄于这个下限,能塞几列就塞几列,剩下的宽度平均分」。 屏幕从 1280 拉到 3440,列数自己从 1 变到 2、3、4,不需要为每种屏幕单独写规则。

规则三页头长一个样

现在有的页面用大标题 + 一句说明(待拍板/待落地/成本),有的只有一个小标题(算力/波次/拍板历史)。 统一成左边大标题 + 一句人话说明,右边放开关和计数,间距一致。

列数随宽度自己变的样子(以待拍板卡片「每列不窄于 620」为例):

< 10321 列
笔记本半屏、侧边贴着别的窗口
1032 – 16631 列(还塞不下第二列)
1440 笔记本全屏
1664 – 25592 列 ← 你现在的 1920 屏在这一档
每列约 826,一行字长度正合适
≥ 25603 列及以上
4K / 带鱼屏自动继续加列,不用改代码

窄屏什么都不会变差:低于门槛就自动回到单栏,和现在长得一模一样。手机/窄窗口的既有断点(760px 那套)原样保留。
