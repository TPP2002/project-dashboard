接法一：Home Assistant（有 HA 的话最省事）

在 HA 里建一个 webhook 自动化，把看板的推送地址填成它给的地址即可。

automation:
  - alias: 看板状态灯
    trigger:
      platform: webhook
      webhook_id: dashboard-events        # 看板的 DASHBOARD_EVENT_WEBHOOK 指到这个地址
    action:
      - service: light.turn_on
        target: { entity_id: light.desk_strip }
        data:
          rgb_color: >-
            {% if trigger.json.event == 'block' %}[224, 70, 60]
            {% elif trigger.json.event == 'pending' %}[240, 150, 30]
            {% else %}[80, 200, 120]{% endif %}
          brightness: 140

接法二：WLED 灯带（没有 HA，直接对灯说话）

WLED 自带 JSON 接口，中间加一个十来行的小转发脚本，把看板的事件翻译成灯带的颜色。

# 收到看板事件 → 直接调灯带（示意，完整脚本随文档交付）
COLORS = {"done": [80, 200, 120], "pending": [240, 150, 30], "block": [224, 70, 60]}

def on_event(ev):                                   # ev = 看板 POST 过来的那条 JSON
    requests.post(f"http://{WLED_IP}/json/state", json={
        "on": True, "bri": 140,
        "seg": [{"col": [COLORS[ev["event"]]], "fx": 2 if ev["event"] == "block" else 1}],
    })
不装这些也不影响任何事。不配那个地址，服务端就一条都不发，代码路径整个不走。 这一项纯属锦上添花，别为了它去买灯。

B. 全部塞进现有下拉，做成一长条折叠		 A。B 省一次开窗，但七类内容滚三屏，找一样东西要翻半天
连击怎么数 A. 宽限那天也算进天数（1 日到今天 = 7 天）
B. 只数真有产出的天（= 6 天）		 A。这个数是给自己看的动力条，读起来顺比精确更重要
进度环上不上项目色 A. 环变项目色实色弧，流光只留薄薄一层外圈
B. 环维持流光不动，只有左边条和下拉着色		 A。总览页正是「一眼分清哪个项目」最要紧的地方；真嫌花随时能退回 B
彩带默认开还是关 A. 默认关，想要自己开（本稿总表写法）
B. 默认开，嫌吵再关		 A。但这条我不确定——你要是觉得「装了新版本该有点动静」，改成 B 也就一行的事
还有一件不用拍但要知会：连击宽限是唯一一个默认就改了旧行为的开关。 别的都是「不点就跟今天一样」，只有这个默认让你的连击数字变大。觉得不该动可以改成默认关。
