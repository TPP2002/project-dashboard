# 灯带与推送

看板可以在完工、有新待拍板、出现阻塞时，向指定地址发送一次 JSON。声音在浏览器播放，灯带推送由看板服务端发送，浏览器关闭后仍可推送。

不配地址就一条不发，配了也只推勾选的三类。地址只从环境变量 `DASHBOARD_EVENT_WEBHOOK` 读取，必须以 `http://` 或 `https://` 开头；网页不能改地址，也不会回显地址。默认未配置。

## 配置地址

以下示例接到 Home Assistant；把 `192.168.1.20` 换成其所在机器的地址。设置后重启看板服务才生效；已有服务请先在原启动窗口按 Ctrl+C 停止，再启动。

Windows 双击启动器：在 `启动看板.bat` 的 `setlocal enabledelayedexpansion` 后、启动服务前加入：

```bat
set "DASHBOARD_EVENT_WEBHOOK=http://192.168.1.20:8123/api/webhook/dashboard-events"
```

Windows PowerShell：在同一个窗口设置并启动看板，子进程会继承这个值：

```powershell
$env:DASHBOARD_EVENT_WEBHOOK = 'http://192.168.1.20:8123/api/webhook/dashboard-events'
& '.\启动看板.bat'
```

macOS / Linux：在启动 `dashboard.sh` 的终端中设置，或者把 `export` 一行放到该脚本启动服务之前：

```sh
export DASHBOARD_EVENT_WEBHOOK='http://192.168.1.20:8123/api/webhook/dashboard-events'
bash ./dashboard.sh
```

进入外观中心的「灯带与推送」，徽章显示「已配置」后，勾选要推送的类别。选择会保存到服务端数据目录 `DASHBOARD_HOME/settings.json`，本机浏览器同时留一份镜像。保存失败会提示并恢复原选择；无法读取服务端时徽章显示「未知」。三类默认都勾选，但没有地址时不会发送。

## 消息与颜色

每次请求使用 `POST`，请求头为 `Content-Type: application/json`。例如：

```json
{
  "event": "done",
  "project": "dashboard",
  "projectName": "项目管理看板",
  "task": "AUD-FUN-PERSONALIZATION",
  "title": "提示音和桌上灯带能跟着看板提醒了",
  "status": "已完工",
  "ts": "2026-09-08T06:22:31.000Z"
}
```

`event` 是 `done`、`pending` 或 `block`；`title` 优先采用卡的人话标题，否则用技术标题。`status` 是读取时卡的当前状态，`ts` 原样保留活动的时间戳。示例里的 `Z` 表示世界协调时间。

| 事件 | 灯色 | 含义 |
| --- | --- | --- |
| `pending` | 橙色 | 有事等你拍板 |
| `done` | 绿色 | 全清 / 完工提示 |
| `block` | 红色 | 有卡阻塞 |

下面的示例按最后收到的事件变色；单张卡的完工消息本身不代表所有项目已全清。

服务启动或首次看到项目时只记录活动基线，不补发历史消息。之后按活动时间升序发出新消息，每个项目每轮最多发送 20 条，多出的丢弃并记录一行警告。每次请求最多等三秒，不重试；未勾选、溢出和失败的事件都不会在以后补发。

## Home Assistant

沿用设计稿第 06 节的自动化，把下面内容合入 `configuration.yaml` 的 `automation` 配置；如果已有 `automation:`，不要重复创建顶层键。如果使用 `automations.yaml`，只放从 `- alias` 开始的列表项。将 `light.desk_strip` 换成自己的灯带实体，保存后重新加载自动化。

```yaml
automation:
  - alias: 看板状态灯
    trigger:
      platform: webhook
      webhook_id: dashboard-events
    action:
      - service: light.turn_on
        target: { entity_id: light.desk_strip }
        data:
          rgb_color: >-
            {% if trigger.json.event == 'block' %}[224, 70, 60]
            {% elif trigger.json.event == 'pending' %}[240, 150, 30]
            {% else %}[80, 200, 120]{% endif %}
          brightness: 140
```

推送地址中的 `/api/webhook/dashboard-events` 要和 `webhook_id` 对应。示例使用局域网地址，接收后把灯带切成相应颜色。

## WLED

没有 Home Assistant 时，可以在看板所在电脑运行一个转发器，把事件转换成 WLED 的 `/json/state` 请求。以下只用 Python 标准库，不需要安装第三方库。保存为 `wled_bridge.py`：

```python
import json, sys
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.request import Request, urlopen

COLORS = {"done": [80, 200, 120], "pending": [240, 150, 30], "block": [224, 70, 60]}
WLED_URL = f"http://{sys.argv[1]}/json/state"

class Bridge(BaseHTTPRequestHandler):
    def do_POST(self):
        try:
            event = json.loads(self.rfile.read(int(self.headers["Content-Length"])))['event']
            body = {"on": True, "bri": 140,
                    "seg": [{"col": [COLORS[event]], "fx": 2 if event == "block" else 1}]}
            request = Request(WLED_URL, data=json.dumps(body).encode(), headers={"Content-Type": "application/json"})
            with urlopen(request, timeout=2) as response: response.read()
        except (KeyError, ValueError, TypeError): self.send_error(400); return
        except OSError: self.send_error(502); return
        self.send_response(204)
        self.end_headers()

HTTPServer(("127.0.0.1", 8765), Bridge).serve_forever()
```

运行 `python wled_bridge.py 192.168.1.30`，把参数换成灯带地址；保持转发器窗口打开，再把看板推送地址设成 `http://127.0.0.1:8765/events` 并重启看板。`fx` 是 WLED 效果编号，此例沿用设计稿的数值；颜色表仍决定橙、绿、红三种含义。

配置好后，新完成一张卡即可观察灯带；关闭「完工」选择后，再完成一张就不会触发该类灯光变化。停止联动时清空或移除环境变量并重启看板即可。
