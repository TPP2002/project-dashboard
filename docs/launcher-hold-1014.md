# 启动器双平台 hold 接入 · 实现说明（DASH-LAUNCHER-NO-SCHED-HOLD-1012 阶段 2）

方案的证据与拍板记录在 `docs/launcher-hold-diagnosis-1014.md`（1014 收敛版）；本文只讲**实现成什么样、怎么用、哪些没验证**。

## 0. 入口与模式

- `启动看板.bat`（Windows）/ `dashboard.sh`（macOS/Linux）是**薄入口**：只检查 Node 在不在，然后整棵交给 `cli/launcher.cjs`。脚本自身的当前目录钉在本检出——**绝不 cd 进发布副本**（Windows 上目录被进程占住就换不了名，下次 `cli release` 换名必失败，0914 实测 EBUSY）。
- **严格模式（默认，不带参数）**：整条启动链——首次依赖安装、现场发布构建、常驻服务——一律经调度台登记；调度客户端不可用 / 共享盘读不动 / 总览心跳超龄（>120 秒）→ **明确拒绝新启动**：不安装、不构建、不起服务、也不动已在跑的实例。**不降级、不裸跑**（负责人拍板 d1：本机与其余默认环境继续强制登记）。
- **独立模式（显式 `--standalone`）**：整条链路不经调度台，供无调度台的用户**主动选择**。缺省永远不等于独立——不存在第三条悄悄绕开调度的路。不认识的参数一律报错，不悄悄转发也不悄悄忽略。
- 发布构建在两种模式下的**构建口径一字不改**：命令形态都是 `node <vite> build`、都建自本次 SHA 的导出树；独立模式省掉的只是"排队"这一层（`cli/release.cjs` 的 `directWebBuild`，印章 `via: standalone-direct`；缺省仍走 `queuedWebBuild`，印章 `via: sched-queued`）。旧发布副本的工具若不认识 `--standalone` 会退回排队构建——没有调度台就如实失败，绝不悄悄伪造许可。

## 1. 启动链（严格模式顺序）

1. **第一闸（先于一切动作）**：加载共享盘客户端（`<share>/sched/bin/sched.cjs`，缺 API 即拒）并只读探一次总览心跳；客户端不可用、共享盘读不动或**心跳龄超过 120 秒**（`HEARTBEAT_MAX_AGE_MS`）都退出码 1，什么都没碰（不动旧实例）。
2. **启动互斥（只护编排，不盖常驻寿命）**：同一份数据根上并发双击只放一个继续——拿不到锁的第二个启动器得到明确"正在编排（安装/发布/挂号起服务）"结果，**绝不挂第二张长期占用单**。锁是登记文件旁的 O_EXCL 原子创建 + 持有者 pid 活性校验；**本次服务起稳（看护把 serverPid 补进登记）就放锁**，起稳之后的每次双击都会重新走完整流程（重新检查/发布、重新判复用或换新）——锁绝不停留在常驻寿命上，否则在跑期间的双击永远绕不进发布检查。锁文件刚独占创建、pid 还没落盘时读到的空/不完整内容＝有人正拿着锁，**拒抢**（绝不当陈锁自动删）；内容坏且超过 30 秒的才按崩溃残骸清理。
3. **预检拒接（只拒不动）**：在跑实例若探活 + 归属 + 票态三重核验判为**无主 / 别人的 / 跨模式**，这里就明确拒接退出——不杀、不冒充、不接管，也不安装、不构建（先于一切重动作）。
4. **首次依赖安装**（`web/node_modules` 缺失时）：严格模式走正式调度 exec（Windows 上 `cmd /c npm install` 包一层——spawn 不认 .cmd）；独立模式本地直跑，同一命令形态。**绝不先停旧服务再安装**。
5. **发布**：起手用发布副本自己的 CLI（没有则用检出的）`release --source <检出>`；语义与旧启动器逐字一致（现场构建 → 同源 → 失败回落旧副本并明示"可能不是最新"）。发布失败照旧回落旧副本——此时副本 stamp 没换，在跑的同版本旧实例自然落在"复用"。
6. **复用 / 换新判定（基于本次发布【之后】的 stamp）**：重新探活 + 读归属 + 回读票态三重验证（§3）。副本 stamp 与在跑实例一致 → 只复用：开浏览器即退，不重复挂号、不重复占核、不动进程；stamp 已换新（主干更新了）而旧实例是自己的 → **先退旧单、确认旧树真的停了**（§4 的停树必须返回 ok），**再**挂新 hold 起新单；退旧失败 → 明确失败退出（码 1），绝不双跑。`DASHBOARD_NO_RESTART=1` 豁免：不动旧实例，复用并明示"你看到的仍是旧版本"。
7. **常驻服务**：严格模式只申请 **1 核**的真实 hold；**hold 先挂号、当拍授予、才由它拉起看护进程**，看护进程**核验真实授予**（§4）后才 spawn server。独立模式直起看护进程（不带票据，只看包装进程死活）。

## 2. 核数与幂等键（实据）

- **1 核** = max(⌈实测突发 0.904 核⌉, 调度最小合法 1)。实测窗口（`launcher-hold-diagnosis-1014.md` §3）：空闲均值 0.0182 核、单轮只读突发 0.904 核。hold 是**记账不是限流**——不外推到未测负载；未来负载变了按同法加窗补测再改。
- **幂等键每次运行唯一**：`serve-<主机名≤16>-<14 位时间戳>-<6 位随机>`（安装单同理 `webinstall-…`）。固定键会让"停了再启"卡死（客户端对已终态票不能按同一键重新挂号）；跨"停-启"的防重靠探活/归属判定 + 启动互斥，不靠键。

## 3. 归属记录与三重验证

- 记录落 `~/.claude/dashboard/launcher-instance.json`（数据域，不进代码仓）：schema、hostname、mode（strict/standalone）、key、ticketId、title、wrapperPid、watcherPid、serverPid、serverCodeRoot、releaseCommit、startedAt（起服务**先落盘**再拉进程；退出补记 serverExitedAt）。
- 探活遵循服务端既有语义：`DASHBOARD_PORT` 指到哪就探哪（设 0 则不扫描——隔离自检场景不碰生产 6060~6068）；只把**同一数据域**（registry/数据根一致，规则与服务端同口径）的在跑实例当自己候选，别的数据域照实告知"不属于这里"并不接管。开浏览器尊重既有 `DASHBOARD_NO_OPEN=1`。
- "复用"必须三重全过：`/api/health` 探活（pid/port/mode/codeRoot/releaseCommit）+ 记录有效（schema/hostname/pid 对得上）+ 票态非终态且票面标题等于本启动器的常驻标题。跨模式（strict 记录 vs standalone 启动，或反向）一律拒接——独立模式起的服务不许被严格模式冒充接管，反之亦然。
- **登记身份守卫**：看护进程带 `--key <生命周期键>` 起，凡写登记先核 key——登记已写着别的生命周期（新双击/别的实例）就**真正零写入**（在进读改写之前就短路，连写盘的机会都不给，别人刚补的字段绝不被旧读回写抹掉）；key 对上才写本次自己的字段。

## 4. 看门狗（账/进程一致，治已实证的撤单缝隙）

诊断卡实证：正式 cancel 一张在跑 hold 单后**票据＝cancelled 而 wrapper/server 仍活**（客户端授予后只等子进程、不监听票态）。共享盘客户端核心不改；由启动器侧对齐：

- 链路：launcher → **hold（真实登记，1 核）** → 看护进程 `core/launcherRuntime.cjs --watch-server` → server（stdio 透传，Ctrl+C/关窗照旧由客户端当拍撤单）。
- **起服务前的授予核验**（口径参照 `cli/scheduledWork.cjs --granted`，复用客户端现行 `validatePermit`）：票读得到、非终态、`SCHED_PERMIT` 在且**票号与本单一致**、validatePermit（类别/作业类型/1 核）通过——四条全过才 spawn server。终态、missing、读取不明、缺许可、错票号一律**不算授予**：不起服务、不写登记、退出码 2；不伪造许可、不裸跑。
- 看护进程每 10 秒（`DASHBOARD_LAUNCHER_WATCH_INTERVAL_MS` 可调，测试用）做一次判定：包装进程死了 / 自己那张票进了终态（passed/failed/cancelled/voided，与 `core/scheduledWork.cjs` 同口径）/ 票已查无 → **停掉自己管理的整棵服务树**、退出码 0；共享盘连续读不动的时长超过预算（默认 **60 秒** = 2 拍 × 30 秒心跳，`DASHBOARD_LAUNCHER_WATCH_SHARE_FAIL_BUDGET_MS`；**故意落在派单员断租销单默认 120 秒窗口之内**——账大概率还在，先停自有进程、再退自己的单，不留无账散兵）→ 停树、**先停进程再退单**、退出码 3。**包装进程死亡而停服成功时，看护优先正式 cancel 自己的票**（账能自己收就不等断租扫），cancel 不成才留断租兜底；票据已被外部 cancel 的不再重复退单。
- **停树必须确认**：Windows `taskkill /pid <pid> /T /F`（整棵树，不只杀父进程）后有界异步轮询确认进程真退了；类 Unix SIGTERM → 有界异步等（不忙等占核）→ 3 秒宽限 → SIGKILL → 再确认；确认不了就**如实返回失败**。启动器换新旧树没停干净 → 明确失败退出（码 1）、保留登记现场，绝不冒充已退、绝不双跑。**绝不按名字扫杀**——只动自己记录里的 pid 树。
- **停不成看护不退场**：停树有界重试（默认 3 次、间隔 2 秒）仍确认不了退出时，看护**留在原地不退出**——调度单不撤（账/进程保持一致）、绝不冒充已停止、也绝不另起新单，直到自有进程真退出（含人工收场）看护才以退出码 1 收场并如实补记退出时刻。看护先退、hold 随后注销而 server 还活着的"账/进程脱节"就是从"停不成也退出"这条缝漏出来的，已堵上。
- 单测实证（假共享盘 + 真子进程）：外部撤单 → 看护退出 0 且记录补上 serverExitedAt；包装进程死 → 退出 0 且**先正式退自己的单**；共享盘坏超预算 → 退出 3 且先停树再退单；缺许可/错票号 → 退出 2 且 server 根本没起；停止失败 → 看护不退出、有界重试、自有进程真退后才以 1 收场；登记 key 不符 → 零写入。

## 5. 退出码

0 成功/复用；1 启动器自身拒绝（参数错、非 git 检出、调度闸/心跳不过、归属拒接、安装/发布无路可走、**换新时旧树停止未确认**）；2 挂号被拒（依赖安装或常驻服务，含**看护没拿到有效授予**）；3 共享盘故障；其他为子进程退出码透传（含看护进程的 130=信号中断）。看护停树未确认时不退出、不撤单，留在原地看住现场；自有进程真退出后才以 1 收场。

## 6. 尚未实测、不冒充（老实账）

- **派单员侧断租 120 秒销单**出自共享盘客户端 USAGE，派单员侧本仓不可审计——本实现只保证自己的预算（60 秒）与兜底逻辑在其**之前**收束，不替派单员作保。
- **类 Unix 缺省共享盘路径读不到**是源码推断（`path.win32.join` 硬编码盘符），未在真机验证；独立模式不依赖共享盘，严格模式在那类机器上会如实拒绝并指路 `--standalone`。
- **SIGKILL 掉看护进程**（杀得连收尾都做不了）会留下孤儿 server，直到下次启动探活报"归属未知、拒接"，由人按提示处置——不做任何自动扫杀。
- **旧发布副本的工具不认识 `--standalone`** 时会退回排队构建：无调度台就如实失败（有调度台则行为不变）。
- **并发互斥的真实多机/多用户并发**只在单机真多进程下测过（同锁文件竞争）；跨机器各自数据根本就互不相干，不做全局锁。
- **心跳超龄阈值 120 秒**、**共享盘预算 60 秒**、**起稳确认上限 10 分钟**、**停树重试 3 次 × 2 秒**均为有依据的定值（120 秒=负责人拍板；60 秒=2 拍 × 30 秒心跳、落在断租销单窗口内），不是实测得出的最优点。
- **起稳确认超时放锁**：排队超过 10 分钟时锁先放行（宁可回到"每次双击重新判"，也不把编排锁死）；此后极小概率出现两张排队 hold 同候一服务的边缘，靠看护 key 守卫与归属判定收敛，未做跨进程排队锁。
- 手动验收项（M1：双平台真机各走一遍严格/独立、重复启动、外部 cancel 实弹、发布换版退旧起新）仍待负责人执行。


预算边界：旧续约最多已过 30 秒，加看护间隔最多 10 秒和连续读失败预算 60 秒，为正常停服保留约 20 秒；停止权限失败仍保留看护并明确恢复边界，不能保证操作系统拒绝终止时强行收场。
