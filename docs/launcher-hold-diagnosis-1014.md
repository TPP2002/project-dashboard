## 0. 结论

1. **漏口有两处（现状）**：① 常驻 server 由启动器前台直起、长期占用不在调度账上（主病）；② 首次使用的 `npm install` 也不排队。两者在**严格模式**下都纳入登记（§4/§5）；"不在菜单/一次性"不构成豁免理由。
2. **实测（主控正式 hold 样本）**：空闲窗口均值 **0.0182 核**；单轮只读 API 窗口均值 **0.904 核**。已证范围仅这两个窗口，不外推"所有负载都证明"（§3）。
3. **核数推荐：1 核** ＝ max(实测窗口向上取整, hold 最小合法正整数 1)。核数不再需要用户代定。
4. **外部撤单缝隙已实证**：正式 cancel 一张在跑 hold 单后，票据＝cancelled 而 wrapper/server 仍活（客户端授予后只等子进程、不监听票态）。共享盘客户端核心不改；由**启动器侧**把账与进程对齐（§4 看门狗）。
5. **共享盘持续失联的实际行为仍只有源码推断**（销单放核、服务照跑），未实测，不冒充（§2）。
6. **方案已定（负责人拍板）**：提供**显式独立模式**供无调度台公开用户选择；本机与其余默认环境**继续强制登记**、失效拒新启动（§5）。实现以同卡阶段 2 正式工单承载。

## 2. hold 语义要点与实证

要点（共享盘客户端，读时快照）：挂号**即授予、不排队**，按核数计入该机已授予核数（L1301–1309）；**只本机单**且恰好一台机器、不许 `codex-build` 类别（L214–221、L596）；**核数为正整数且 ≥1**（L1330、L202/220）；租约每 `--beat-sec`（默认 30 秒）续期，续约失败只打日志下拍重写（L1310–1325、L1386–1392）；**服务退出当拍撤单**、退出码透传（L1393–1399）；包装进程被杀 → 续约停 → **派单员断租超时自动销单（默认 120 秒）**，撤单未送达也走这条兜底（L1349–1355、L2392）；退出码 2＝挂号被拒、3＝共享盘故障（L2383/2393）；resident 单**不参与**核数历史自动纠正（L590–593）。

**实证缝隙（R2，已测）**：
- 17:28:15 UTC，主控对**自己**的 hold 单 `tk-86594d0e1efd04bb0f24` 正式 cancel，执行成功；
- 17:29:27 UTC 回读票据＝**cancelled**，而 wrapper(pid 25984) / server(pid 26376) **仍活**——与源码判据一致：hold 授予后只等子进程退出、不监听票态（L1357–1366 仅等授予段轮询）。
- 样本随后经另一张正式调度单 `tk-966ce98a03c2a836252c` 按 PID/父链/命令核验，只清理了这个自有样本（本工单返工时复探 6060~6068 全部静默，实证附录 A）。
- **结论：账与进程一致不能依赖共享盘客户端；必须由启动器自己管理（§4 看门狗）。**

**仍属源码推断（未实测，不冒充）**：共享盘持续不可读超过租约门槛 → 派单员销单放核、服务照跑；阈值"默认 120 秒"出自 USAGE（L2392），派单员侧本仓不可审计。

## 4. 方案（只方案，不实现兼容层）

**职责划分：一个 helper + 双平台薄入口。** bat / sh 只留环境检查与调用（`exec` 语义照旧）；helper 承担全部逻辑（可同仓新增文件；触及生产文件的改动一律属阶段 2 正式工单，不建兼容层、不动安装包/托盘）。

helper 步骤（原则已定；具体接线为可逆实现细节）：

1. **探活与归属判定**：先探 6060~6068 的 `/api/health`（探法同 `cli/release.cjs` `serviceStatus` L491–530），**按归属分三路**：
   - **无实例** → 正常启动（严格模式经 hold 登记；独立模式直起）。
   - **有实例且是自己已登记的**（归属凭据——如启动器落盘的 pid/单号对应记录或票面约定——属实现细节）：同版本 → 复用并退出、不重复挂号；旧版本 → 按既有换新语义接管换新。
   - **有实例但无登记或归属未知** → **不冒充新 hold 覆盖、不接管、不杀**；停下并明示用户（交互形态实现期定）。
   原则：同版本重复启动只复用**自己已登记的**实例；**不接管别人的服务**。server 内建的复用/接管行为（`server.cjs` L1685–1712）如何与这条归属规则并轨（helper 预检、`DASHBOARD_NO_RESTART` 等）属阶段 2 生产改动范围。hold 只是记账，**不许用两单占两份核冒充单实例**。
2. **装依赖与发布构建**：**严格模式下也必须登记**——首次 `npm install` 与现场构建走调度客户端的 run 型结账单（与重活同口径），漏口②在严格模式内关死；**独立模式下全部启动链路可运行、不经调度**——现场构建不得仍卡在 `cli/release.cjs` L189–193 的调度构建（独立模式直跑构建），具体接线阶段 2 定。"发布失败回落旧副本"语义照旧（bat L80–94）。
3. **hold 包装起服务**：`sched.cjs hold --project dashboard --cores 1 --title … --root <检出> -- node <副本>/server/server.cjs`。cwd 与 `--root` 都留检出（EBUSY 边界）。**幂等键：每次运行唯一**（如 `dashboard-server-<hostname>-<启动时间戳+随机>`），**不用固定键**——客户端对已终态票不能再按同一键重新登记（票号由键派生、挂号回执做身份校验：L625；客户端自带键即"时间戳+随机"式，L1422–1424），固定键会让"停了再启"卡死。单次运行内的重复挂号仍被幂等吸收；跨"停-启"的防重靠第 1 步探活与归属判定，而不是靠键。category/workType 沿用合法缺省 `other`/resident 语义；核数 1 来自 §3 实据，未来实测变化按同法更新。
4. **账与进程一致（看门狗，治 §2 实证缝隙）**：外部撤单后客户端不会停服务，故由**启动器侧**在包装之外周期性回读自己那张单的票态（`sched.cjs status`；终态口径与 `core/scheduledWork.cjs` 一致：passed/failed/cancelled/voided），见到终态即**停掉自己管理的服务**——**账停、进程也停**。反方向（进程死 → 断租 → 派单员回收）客户端已天然覆盖。实现形态（轮询间隔、走子进程还是读票文件）留实现时定；**不改共享盘客户端核心**。
5. **退出路径**照旧：Ctrl+C / 关窗 → 服务退 → hold 当拍撤单（L1393–1399）。

**范围纪律**：只改**两个启动器**（及为承载方案所需的阶段 2 生产接线）；不加 dev 实例（6070 段）新开关；不动安装包/托盘（`packaging/**`）；不建兼容层。模式开关、装依赖/构建的登记接线、归属凭据、server 归属规则并轨，全部属阶段 2 正式工单的生产改动，本卡不顺手实施。

## 5. 模式边界（负责人已拍板，方案已定）

**拍板记录**：负责人选定「**提供显式独立模式，本机继续强制登记**」——保留其他 GitHub 下载者也能运行（d1，已由主控写回看板）。

- **严格模式（默认）**：零豁免不变——**整条启动链**（首次 `npm install`、现场构建、常驻服务）都经调度登记；调度客户端不可用 / 共享盘故障时**拒绝新启动**（与 `cli/scheduledWork.cjs` L34"排队客户端不可用，重活未启动"同口径），不降级。
- **显式独立模式**：供无调度台公开用户主动选择；**全部启动链路可运行、不经调度**——含装依赖与现场构建，现场构建不得仍卡在 release 的调度构建（§4 步骤 2）；常驻服务直起、无 hold。
- 判别信号问题就此解决：不再试图从缺省配置推断"是否公开用户"（缺省永远有值），**由显式模式开关本身判别**。本机 settings.json 实测无 `schedShare` 键、落缺省 `F 盘的 calib-share 目录`（实测记录见附录 A）——严格模式下这没有歧义：默认即强制登记。
- 类 Unix 的缺省盘符路径读不到：**源码推断，未实测**；独立模式不依赖共享盘，该缺省不构成障碍（推断层面）。
